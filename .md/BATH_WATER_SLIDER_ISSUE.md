# 욕탕 관리 화면·컴퓨터 입력 현황

## 사용자 보고

- 순환도·목표 수온 슬라이더 손잡이가 용량 한계를 넘어 드래그되고, 마우스를 놓은 뒤에도 넘어간 위치에 남는다.
- 어떤 용량(설치 정격용량 또는 현재 가동용량)을 기준으로, 어느 설정값에서 재현되는지는 아직 확인하지 않았다.

## 확정 계약과 코드상 차이

- `.md/QNA_FEATURE_SPEC.md` Q6·Q18: 드래그 중 즉시 적용하되, 설정 가능한 한계에서 손잡이가 더 움직이지 않고 제한 이유를 표시한다.
- Q32: 설정 예약의 상한은 **설치 정격용량**이다. 현재 가동용량만 부족한 경우 설정을 보존하고 해당 효과를 중지한다.
- 현재 UI는 요청 결과의 `CommittedValue`로 손잡이를 즉시 되돌리지 않는다. 제한 결과가 기존 설정값과 같으면 subsystem의 변경 알림도 생략되므로 손잡이가 요청 위치에 남을 수 있다. 이 부분은 코드상 원인 후보이며 실제 재현 조건과 분리해 둔다.

## 미확인·후속 조사

- 재현 시 설치 정격용량, 현재 가동용량, 전체 예약량과 선택 욕탕의 요청값·확정값을 구분해 기록한다.
- 손잡이 위치뿐 아니라 상세 패널의 순환도·목표 수온과 capacity 표시가 실제로 변경되는지 확인한다.
- 이 문서는 현황 기록이다. 이번 단계에서 코드·위젯·에셋은 수정하지 않았고 PIE 재현도 하지 않았다.

## 컴퓨터 포커스아웃: 사용자 보고

- `E`로 컴퓨터에 포커스인한 뒤 아무것도 클릭하지 않고 다시 `E`를 누르면 포커스아웃되지 않는다.
- 화면을 한 번 클릭한 다음 `E`를 누르면 포커스아웃된다.
- 클릭 없이 두 번째 `E`만으로 나가는 것이 기대 동작이며, 클릭 선행 조건은 승인된 계약에 없다.

## 코드상 확인과 미확정 원인

- `AFirstPersonCharacter::InteractStartInput()`은 컴퓨터 입력을 캡처 중이면 클릭 여부와 관계없이 `RequestEndComputerUse()`를 호출한다.
- 포커스인 완료 시 `FInputModeGameAndUI`가 컴퓨터 화면 Widget에 키보드 포커스를 지정한다. 첫 클릭 후에만 `E`가 작동하는 현상은 입력 포커스/라우팅 문제로 의심되지만, PIE 입력 이벤트를 추적하지 않아 원인을 확정하지 않았다.
- 기존 자동화 테스트는 `InteractStartInput()`을 직접 호출하므로 실제 키보드 입력·Widget 포커스 경로를 검증하지 못한다.
- 후속 조사: 클릭 전후 두 번째 `E`가 `InteractStartInput()`에 도달하는지, 포커스된 Widget·Viewport와 Enhanced Input의 `Started/Completed` 상태를 비교한다. 이 항목 역시 기록만 했으며 코드는 수정하지 않았다.
