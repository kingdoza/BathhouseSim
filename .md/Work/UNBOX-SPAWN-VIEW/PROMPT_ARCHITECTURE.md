# PROMPT_ARCHITECTURE — UNBOX-SPAWN-VIEW 플레이어 앞 생성 위치를 카메라 정면 기준으로

- 작업 ID: `UNBOX-SPAWN-VIEW`
- 단계: 기능 명세
- 상태: 진행

사용자 답변 전 초안이다. `QNA_FEATURE_SPEC.md`의 추천안을 가정해 썼고, 추천안과 다른 답이 오면 표시한 부분을 고친다. 승인 전에는 아키텍처 입력이 아니다.

## 1. 목적과 범위

사용자 요청 원문: "언박싱등의 플레이어앞에 물체가 생길때 너무 아래에서 생기는데 생성위치가 플레이어 카메라 정면 기준이 맞는지 확인."

플레이어 행동과 관찰 결과로 다시 쓰면 다음과 같다.

- 플레이어가 무언가를 해서 자기 앞에 새 물체가 생길 때, 그 물체는 플레이어가 보고 있는 화면 정면(카메라 시선 방향)에 나타나야 한다.
- 지금은 앞을 똑바로 보고 상자를 열어도 물품이 발밑 가까운 낮은 곳에 생겨 화면 아래로 벗어나 보이지 않는다.

이번 작업은 "플레이어 앞에 새 물체를 만드는 경로"의 생성 위치 기준만 바꾼다. 무엇이 생기는지, 몇 개가 생기는지, 생긴 뒤의 물리·상호작용 규칙은 바꾸지 않는다.

## 5. 동작 계약 (추천안 가정)

### 5.1 시작 조건과 입력

- 개봉: 배송 상자를 들고 LMB(기존과 같음). 컴퓨터·배치 모드가 LMB를 먼저 가져가는 우선순위 유지.
- 봉투(Q1 B일 때): 집게를 들고 봉투에 쓰레기가 1개 이상일 때 RMB(기존과 같음). 조준 대상과 무관.
- 입력 순간의 카메라 위치·시선 방향이 생성 기준이다. 시선은 위·아래 각도(pitch)를 포함한다(Q2 A).

### 5.2 생성 위치

- 기준점: 카메라 위치에서 시선 방향으로 "생성 거리"만큼 나간 지점.
- 생성 거리는 카메라에서 무리(봉투는 봉투 하나)의 가장 가까운 부분까지의 시선 방향 거리다(Q3 B). 무리가 커지면 무리 중심은 더 멀어지고, 무리가 카메라를 덮어 화면을 가리지 않는다.
- 무리는 시선 방향 기준점에 대해 좌우·위아래 가운데 정렬로 보인다. 정확한 정렬 기준(무리 bounds 중심 등)은 설계에 맡긴다.
- 물품은 위·아래를 보고 열어도 선 자세이고, 좌우 방향(yaw)만 무작위다(Q27 A 유지). 봉투는 지금처럼 플레이어가 보는 좌우 방향으로 선다.
- 수평으로 보고 열면 생성 순간 무리 또는 봉투가 화면 중앙 부근에 보인다.
- 아래를 보고 열면 앞쪽 아래, 바닥보다 위에 생긴다. 바닥에 닿거나 파고든 채 생기지 않는다.
- 위를 보고 열면 앞쪽 위 공중에 생기고 떨어진다. 천장에 닿거나 천장 위에 생기지 않는다.

### 5.3 막혔을 때 (Q5 B 가정)

순서대로 시도하고 처음 성공한 곳에 생긴다. 각 단계 모두 기존 금지 조건(벽·바닥·천장·기존 물체·손님 안 생성 금지, 벽·천장 너머 생성 금지, 생성 직후 겹침이 풀리며 밀려나도 벽·천장에 박혀 시작하지 않을 여유)을 지킨다.

1. 시선 방향 당김: 생성 거리를 카메라 쪽으로 줄여 가며 시선 방향 위의 빈 공간을 찾는다.
2. 바닥 정면: 현재 계약의 정면 규칙(발바닥 기준 수평 전방, 바닥 근처 높이, 수평 당김)을 쓴다. 위를 보거나 천장이 낮아 1이 실패해도 앞쪽 바닥 위에 생기게 한다.
3. (개봉만) 머리 위 쌓기: 현재 계약 그대로.
4. (개봉만) 최후 수직 쌓기: 현재 계약 그대로. 개봉은 항상 성공한다.
- 봉투는 1·2가 모두 실패하면 `봉투를 놓을 공간이 없음`을 표시하고 봉투 개수·집게·월드가 그대로다(현재 실패 계약 유지).

### 5.4 생긴 뒤의 물리 (Q4 A 가정)

- 생긴 위치에서 추가 속도 없이 중력으로 떨어진다. 공중에 생기면 그 높이에서 떨어진다.
- 개봉 물품은 지금처럼 같은 상자 물품끼리만 일부 겹쳐 생기고 엔진 충돌 해소로 서로 밀어내며 튄다(Q29 B, Q30 B 유지). 겹침 정도 조정값과 튐 세기 관계(SHOP-043)는 그대로다.
- 높은 곳에서 떨어져도 바닥 아래·벽 너머·맵 밖으로 빠지지 않는다. 빠지면 기존 맵 밖 복구가 생성 위치로 되돌린다.
- 생긴 물체는 플레이어와 손님을 밀지 않는다(기존 Pawn 무시 유지). 아래를 보고 열어 발 근처에 떨어져도 플레이어가 밀리거나 갇히지 않는다.

### 5.5 즉시 피드백과 완료 시점

- 개봉: LMB를 누른 순간 상자가 사라지고 빈손이 되며 같은 순간 물품이 생긴다(기존과 같음). 진행 표시 없음.
- 봉투: RMB를 누른 순간 봉투가 생기고 집게 봉투 개수가 0이 된다(기존과 같음). 실패하면 HUD 실패 문구만 바뀐다.
- 새 HUD 문구·표시는 없다.

### 5.6 실패·취소·복원

- 개봉은 실패하지 않는다(항상 성공 유지). 내부 생성 실패로 개봉이 취소되면 지금처럼 상자는 손에 남고 생긴 물품은 하나도 남지 않는다.
- 봉투 실패 시 집게 봉투 개수, 월드, 손에 든 집게가 그대로다.

## 6. 유지 계약

- 무엇이 생기는지(주문 내용 수량만큼의 설비 아이템·가득 찬 품목 박스, 묶은 봉투 하나와 쓰레기 수)는 바꾸지 않는다.
- 무리 모양: 물품 수·크기만큼 커지는 3차원 무작위 무리, 고정 반경 없음, 같은 상자라도 열 때마다 배치가 다름(SHOP-038~040).

- 컴퓨터·배치의 LMB 우선순위, 집게 RMB 조준 무관.

## 9. 수직 구현 판단 (Q6 A 가정)

- 위치·회전·물리 감각이 수용 기준이고 두 경로에 공통 적용되므로 수직 구현을 쓴다.
- 대표 시나리오: 배송 상자 개봉 USV-001~014. 사용자 PIE 승인 뒤 봉투 묶기(USV-015~017)를 별도 작업 ID로 확장한다.
- Content 변경은 예상하지 않는다. 기존 조정값의 기본값 변경이 생기면 Config·Blueprint 기본값 범위다.

## 10. Editor 사전 조사

생략한다. 새 계약은 런타임 카메라 위치·시선 방향, 기존 collision·물리 계약만 기준으로 하며 Blueprint의 capsule·카메라 오프셋·FOV 값이 달라도 계약 문장이 같다. 2.1의 "화면 밖" 설명은 Source 기본값 추정이며 PIE에서 사용자가 확인한다.

## 11. 비목표

- 생성되는 물체의 종류·수량·크기, 무리 모양 규칙, 튐 세기 규칙 변경.
- 생성 순간 추가 속도·애니메이션·연출 추가.
- G 내려놓기·Q 회수·배송 지점·플레이어와 무관한 생성 경로 변경.
- 카메라 pitch 제한, FOV, 캐릭터 capsule 변경.

## 12. 설계에 맡김

- 시선 방향 위 무리 정렬 기준과 "가장 가까운 부분" 판정 방법.
- 시선 당김·바닥 정면·머리 위 단계의 시도 횟수와 계산 비용 배분.
- 기존 조정값 재사용 또는 새 조정값 추가, 두 경로의 계산 공유 여부.
- 시야 검사 기준점(현재 capsule 중심)을 카메라로 바꿀지 등 벽 너머 금지 판정 방법.
