## 현상 1 — 슬라이더 손잡이가 용량 한계를 넘어 남음

욕탕 관리 화면의 순환도·목표 수온 슬라이더 손잡이가 용량 한계를 넘어 드래그된다. 마우스를 놓은 뒤에도 넘어간 위치에 남는다.

### 재현 조건
1. 컴퓨터 욕탕 관리 화면에서 욕탕을 선택한다.
2. 순환도 또는 목표 수온 슬라이더를 용량 한계 너머까지 드래그한다.
3. 마우스를 놓는다.

(어떤 용량 기준에서, 어느 설정값에서 재현되는지는 확인되지 않았다.)

### 기대 동작
(확정 명세: `.md/QNA_FEATURE_SPEC.md` Q6·Q18·Q32)
- 드래그 중 값이 즉시 적용되고, 설정 가능한 한계에서 손잡이가 더 움직이지 않으며 제한 이유가 표시된다.
- 설정 예약의 상한은 설치 정격용량이다. 현재 가동용량만 부족하면 설정은 보존되고 해당 효과만 중지된다.

### 실제 동작
손잡이가 한계를 넘어 움직이고, 놓은 뒤에도 넘어간 위치에 남는다.

## 현상 2 — 컴퓨터 포커스아웃이 클릭 없이는 안 됨

E로 컴퓨터에 포커스인한 뒤 아무것도 클릭하지 않고 다시 E를 누르면 포커스아웃되지 않는다. 화면을 한 번 클릭한 다음 E를 누르면 포커스아웃된다.

### 재현 조건
1. 컴퓨터를 조준해 E로 포커스인한다.
2. 아무것도 클릭하지 않고 E를 한 번 더 누른다.

### 기대 동작
클릭 없이 두 번째 E만으로 포커스아웃된다. (클릭 선행 조건은 승인된 계약에 없다.)

### 실제 동작
포커스아웃되지 않는다. 화면을 한 번 클릭한 뒤에는 E로 포커스아웃된다.

## 영향 범위

| 현상 | 대상 |
|---|---|
| 1 | 욕탕 관리 화면(컴퓨터)의 순환도·목표 수온 슬라이더 |
| 2 | 컴퓨터 포커스 전반 |

## 재현 빈도

미기록 (사용자 보고 기준)

## 미확인

- 현상 1: 재현 시 설치 정격용량, 현재 가동용량, 전체 예약량, 선택 욕탕의 요청값·확정값. 손잡이 위치 외에 상세 패널의 순환도·목표 수온·capacity 표시가 실제로 변경되는지.
- 현상 2: 클릭 전후에 두 번째 E가 입력 처리(`InteractStartInput()`)에 도달하는지, 포커스된 Widget·Viewport와 Enhanced Input의 Started/Completed 상태 차이.

## 조사 메모 (원본에서 옮김, 원인 미확정)

- 현상 1: 현재 UI는 요청 결과의 `CommittedValue`로 손잡이를 즉시 되돌리지 않는다. 제한 결과가 기존 설정값과 같으면 subsystem의 변경 알림도 생략되어 손잡이가 요청 위치에 남을 수 있다(코드상 원인 후보).
- 현상 2: `InteractStartInput()`은 컴퓨터 입력 캡처 중이면 클릭 여부와 관계없이 `RequestEndComputerUse()`를 호출한다. 포커스인 완료 시 `FInputModeGameAndUI`가 컴퓨터 화면 Widget에 키보드 포커스를 지정하므로 입력 포커스/라우팅 문제로 의심된다. 기존 자동화 테스트는 `InteractStartInput()`을 직접 호출해 실제 키보드 입력·Widget 포커스 경로를 검증하지 못한다.

## 수정 결과

- 원인: 현상 1 — `SSlider`가 드래그 중 손잡이를 먼저 옮기는데 상세 패널 widget이 요청 확정값으로 되돌리지 않았고, 한계에서는 subsystem이 변경 알림 없이 반환하며 주기 갱신도 cache 비교에 막혔다. 현상 2 — 포커스인 때 키보드 focus를 월드 화면 widget에 주던 코드(리포트 시점)로 E가 game viewport에 오지 않았다.
- 유입 단계: 현상 1 욕탕 관리 화면 native widget 구현 단계, 현상 2 컴퓨터 포커스 구현 단계(`61f72c1` CMP-001 설계에서 이미 Source 수정됨).
- 검출 실패 단계: 코드 리뷰·자동화 — 기존 테스트가 slider 값을 직접 쓰고 `InteractStartInput()`을 직접 호출해 실제 드래그·키보드 focus 경로를 거치지 않음.
