## 재작업과 PIE

### Q1. 사용자 PIE 실패 뒤의 재작업 프롬프트는 누가 쓸까요?

통합 리뷰가 없어져 `PROMPT_UNREAL_R.md`의 작성자가 없고, PIE에서 나온 코드 재작업의 `PROMPT_IMPLEMENTATION_R.md` 작성자도 비어 있습니다. R 프롬프트를 쓰려면 먼저 PIE 실패의 원인을 진단해야 하므로, 진단을 누가 하는지도 함께 정합니다.

- A: 원인 진단과 재작업 프롬프트를 코드 리뷰 역할이 맡는다. PIE 버그 수정 뒤에는 새 리뷰어를 쓰는 규칙에 따라, 새 리뷰어가 버그 리포트와 코드를 근거로 진단한다.
  - 구현 문제: 그 리뷰어가 `PROMPT_IMPLEMENTATION_R.md`를 쓴다. 코드 리뷰 실패 때와 같은 작성자가 되어 소유권이 하나로 유지된다. 수정 후 재검증은 같은 리뷰어를 재개한다.
  - 설계·명세 문제: R 프롬프트 없이 아키텍처나 기능 명세로 복귀한다. PIE에서 발견된 문제이므로 복귀 기록(RET)이 아니라 버그 리포트의 수정 결과(유입 단계 포함)로 기록한다.
  - Editor 설정 문제: Unreal Editor 읽기 전용 조사로 asset 상태를 확인하고, 마스터가 그 결과로 `PROMPT_UNREAL_R.md`를 쓴다. Editor 역할은 자기 입력 프롬프트를 쓰지 않는다.
- B: 마스터가 직접 진단하고 `PROMPT_IMPLEMENTATION_R.md`와 `PROMPT_UNREAL_R.md`를 모두 쓴다.
- C: PIE에서 나온 재작업은 원인과 관계없이 항상 아키텍처 단계가 진단하고 프롬프트를 쓴다.
- 공통: R 프롬프트 첫머리에 `- 출처: 코드 리뷰 2회차` / `- 출처: 사용자 PIE (버그 리포트 경로)`를 넣어 리뷰 루프 횟수와 PIE 재작업을 구분한다.
- 추천안: A — `PROMPT_IMPLEMENTATION_R.md`의 작성자가 코드 리뷰 하나로 유지되고, 코드 진단이 마스터 대화를 키우지 않습니다. 이미 정한 "PIE 버그 수정 뒤에는 새 리뷰어" 규칙과도 맞아, 결함을 놓친 원래 리뷰어가 진단하지 않습니다. B는 소유권이 둘로 갈리고 마스터 컨텍스트가 커지며, C는 단순 구현 오류에도 아키텍처 에이전트를 불러 비용이 큽니다.
- 답변:  A

### Q2. 진행 중 작업의 PIE 실패와 완료 뒤 발견한 버그를 어떻게 나눌까요?

- B: A와 같지만, 완료된 작업에서 발견된 버그는 마스터 판단으로 진행 중 작업보다 먼저 처리한다.
- 추천안: A — 끼어들기 판단은 사용자 우선순위의 문제라 마스터가 정하지 않는 편이 안전합니다. 전환 절차는 P3의 asset 손상을 막습니다.

### Q10. Claude 마스터는 Codex 워커를 어떤 역할에 쓸까요?

마스터는 Claude로 확정됐다(2026-10-01 사용자 지정). Claude 하위 에이전트가 기본이고, Codex는 `codex exec`(비대화 실행, `-o`로 최종 보고를 파일로 저장)와 `codex exec resume`(재개)으로 부른다.

공통 기준(어느 선택지든 적용):

- 구현과 그 구현의 코드 리뷰는 서로 다른 모델 계열이 맡는다. 같은 계열의 맹점을 피하기 위해서다.
- 기능 명세와 사용자 질문이 오갈 수 있는 작업은 Claude가 맡는다. `codex exec`는 실행 중에 사용자에게 질문하거나 승인을 받을 수 없다.
- Unreal Editor 역할은 한 도구가 맡는다. Editor 세션 소유권·MCP 세션·화면 작업 모드를 두 도구가 나눠 가지면 Editor 중복 실행 위험이 생긴다.
- 한 작업 안에서 한 역할에 정한 도구는 바꾸지 않는다. 재개는 같은 도구 안에서만 된다. 예외는 반복 오판으로 계열을 바꿀 때뿐이다.
- 같은 지적이 반복돼 루프 한도에 걸리면, 아키텍처 복귀 전에 다른 계열 에이전트로 한 번 교체할 수 있다.

- A: 구현은 Codex, 나머지(기능 명세·아키텍처·코드 리뷰·Unreal Editor·회고)는 Claude
- B: 코드 리뷰만 Codex, 나머지는 Claude
- C: 전부 Claude. Codex는 반복 오판 교체와 사용자 지시 때만
- 추천안: A — 현재 빌드 정책(`AGENT_WORKFLOW.md`의 UE 5.8 Build Policy)은 Codex shell 기준으로 검증돼 있고, Codex 설정(`sandbox = "elevated"`, 자동 승인 검토자)으로 비대화 빌드가 가능합니다. 가장 토큰을 많이 쓰는 구현을 Codex가 맡아 사용량도 나뉩니다. 리뷰·Editor·명세는 마스터와 같은 Claude라 재개와 사용자 질문이 자연스럽습니다.
- 연쇄: B를 고르면 Codex 리뷰어는 빌드 해시가 같을 때 읽기 전용으로 실행합니다. C를 고르면 "구현과 리뷰는 다른 계열" 기준을 지킬 수 없으므로 이 기준을 뺍니다.
- 답변: A
