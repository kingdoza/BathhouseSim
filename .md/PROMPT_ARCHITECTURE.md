# 기능 계약 — 욕탕 물 순환·가열·냉각과 컴퓨터 제어

## 문서 역할

이 문서는 욕탕 물 순환·가열·냉각 설비와 컴퓨터 제어의 사용자 동작 계약이다. 플레이어가 조작하는 값, 월드와 UI에서 관찰할 결과, 용량 제한, 실패·취소·복구, Editor authoring 기대와 수용 시나리오를 정의한다.

이를 실현할 클래스, Component, Subsystem, API, 데이터 구조, Tick·timer·event, transaction, Widget native 계층과 파일 구성은 정하지 않는다. 해당 기술 설계는 이 계약이 사용자에게 승인된 뒤 아키텍처 단계가 결정한다.

## 기능 계약 상태

- 추가 요청(2026-09-23): 기본 비가동, 보일러 석탄·쿨러 드라이아이스 삽 투입, 순환기 인력 작업, 시간 감소 가동수치와 원형 계기 바늘을 추가한다. `.md/QNA_FEATURE_SPEC.md` Q29~Q47 답변 완료. Q32는 A(설치용량 기준 예약, 가동용량 부족 시 설정 보존·해당 효과 정지·복구 시 자동 재개), Q45~Q47은 모두 A다. 이번 확장의 사전 조사와 기능계약 본문 반영은 아직 완료되지 않았다.
- 아래 승인 상태와 본문은 Q1~Q28의 기존 물 관리 범위에 해당한다. 본문의 항시 가동 및 노동·연료 비목표는 이번 확장으로 대체할 대상이며, 노동 가동 확장 자체는 아직 승인된 설계 입력이 아니다.
- 기준 사용자 선택: `.md/QNA_FEATURE_SPEC.md` Q1~Q28 전체 답변 완료
- Editor 근거: `.md/REPORT_UNREAL_DISCOVERY.md`, 2026-09-22 UE 5.8.2 Unreal MCP 읽기 전용 조사 완료
- 현재 상태: 2026-09-22 사용자 최종 승인 완료, 아키텍처 입력으로 사용 가능
- 미확정 사용자 선택: 없음
- 아키텍처·구현 시작 조건: 충족

## 목적

- 플레이어가 순환기·보일러·쿨러를 배치해 목욕탕 전체의 순환·가열·냉각 총용량을 확보한다.
- 플레이어가 컴퓨터에서 욕탕별 순환도와 목표 수온을 아날로그 방식으로 조절한다.
- 순환으로 오염도를 낮추고, 순환과 가열·냉각 용량으로 목표 수온에 도달·유지한다.
- 모든 욕탕의 설정이 현재 설치된 설비의 종류별 총용량 안에서 예측 가능하게 제한된다.
- 실제 배치영역과 욕탕 위치를 반영한 컴퓨터 그리드에서 관리 대상을 선택한다.

## 현재 확인된 동작과 Editor 기준선

### 컴퓨터

- `/Game/Bathhouse/Blueprints/Computer/BP_BathhouseComputer`는 현재 `ComputerMesh`, `ScreenWidget`, `FocusCamera`를 가진다.
- 현재 화면은 `/Game/Bathhouse/UI/WBP_ComputerSampleScreen`이며 World Space `1024×576`, hardware input 비활성 상태다.
- 현재 별도 `/Game/Input/Actions/IA_ComputerClick`은 없고 `IA_PrimaryUse`가 LMB에 연결돼 있다.
- 현재 화면의 실제 WidgetTree와 필수 BindWidget 이름·타입은 MCP 기능 범위 밖이라 확인하지 못했다.
- 기존 컴퓨터 포커스는 월드를 pause하지 않고, 사용 중 이동·시점·월드 상호작용을 억제하며, 종료 시 플레이어 입력과 view를 복원하는 계약을 가진다.

### 욕탕

- `/Game/Bathhouse/Blueprints/Facility/BP_Bath`의 실제 parent는 `/Script/BathhouseSim.BathhouseBathFacilityActor`다.
- 욕탕 하나에는 독립된 이용 슬롯 3개가 있다.
- 실제 placement footprint는 `300×240cm`이고 Actor local 설치 바닥은 Z=0이다.
- 현재 욕탕에는 수위·급수·배수·수면·급수밸브·배수레버 표현이 있으나 수온, 목표 수온, 오염도와 순환도 값은 없다.
- DefaultMap에는 같은 욕탕 Blueprint 인스턴스가 2개 있다. 두 번째 인스턴스의 시각 mesh 누락과 Approach Z override는 현재 결함이며 목표 동작으로 간주하지 않는다.

### 배치영역

- DefaultMap의 욕탕을 허용하는 PlacementZone은 현재 하나다.
- world 위치는 `(600,-100,0)`, 회전은 0이며 full size는 `2800×1800cm`다.
- world 범위는 X `[-800,2000]`, Y `[-1000,800]`이고 UI는 `+X`를 위쪽, `+Y`를 오른쪽으로 표시한다.
- 실제 placement grid는 현재 `20cm`다. 컴퓨터 지도에는 모든 minor cell을 그리지 않고 큰 간격의 보조선만 표시한다.

### 신규 설비 asset

- 순환기와 쿨러에 대응하는 기존 Blueprint, mesh와 Placement Definition은 확인되지 않았다.
- `/Game/Bathhouse/Meshes/boiler`와 material은 존재하지만 현재 단순 StaticMeshActor 표현이고 배치 가능 보일러 설비가 아니다.
- 이 후보 mesh를 최종 보일러 외형으로 사용할지는 이 기능 계약이 결정하지 않는다.
- 순환기·보일러·쿨러의 실제 placeable asset과 Definition은 이후 설계·Editor 단계의 대상이다.

### 문서와 asset 불일치

- 실제 placement grid `20cm`, Bath footprint X extent `150`, major grid interval `5`가 기존 Unreal 문서 일부와 다르다.
- 실제 욕탕 수면·marker·밸브·레버·Niagara authoring도 기존 Unreal 문서 일부와 다르다.
- 기능 결과는 MCP로 확인한 현재 asset을 기준선으로 삼되, 이 불일치를 새 기능의 목표값으로 고정하지 않는다.

## 핵심 용어와 단위

- `용량 포인트`: 순환·가열·냉각의 제공량과 요구량을 표시하는 공통 숫자 단위다.
- `총 순환용량`: 정상 배치된 모든 순환기 인스턴스의 순환용량 합이다.
- `총 가열용량`: 정상 배치된 모든 보일러 인스턴스의 가열용량 합이다.
- `총 냉각용량`: 정상 배치된 모든 쿨러 인스턴스의 냉각용량 합이다.
- `요구량`: 모든 설치 욕탕이 현재 설정으로 예약한 종류별 용량 합이다.
- `순환도`: 욕탕별 `0~100%` 연속 조절값이다.
- `실온`: 모든 욕탕이 공유하는 프로젝트 전역 기준 수온이며 기본 `20°C`다.
- `목표 수온`: 욕탕별 `10~50°C`, `1°C` 단위 설정값이다.
- `실제 수온`: 현재 욕탕 물의 관찰 가능한 수온이다.
- `오염도`: `0%=깨끗함`, `100%=최대 오염`인 욕탕별 연속 값이다.
- `%p/s`: 1초에 변하는 퍼센트 포인트 단위다.
- `실제 입욕 중`: 손님이 욕탕 안의 실제 입욕 행동 구간에 있는 상태다. 예약·이동·입장·퇴장·탐색·knockdown은 포함하지 않는다.

## 유지해야 하는 기존 계약

- 욕탕의 물 양은 계속 `0~100%` 범위다.
- 모든 욕탕은 전역 공통 입욕 임계 수위 `80%`를 사용한다.
- 수위 80% 미만인 욕탕은 손님 예약·입장 후보가 아니며, 사용 중 80% 미만이 되면 기존 강제 퇴장·재탐색 계약을 따른다.
- 기존 급수밸브·배수레버의 독립 조작, 급수·배수 순유량, 만수 자동 급수 종료와 수면 표현을 유지한다.
- 기존 실제 입욕시간, 60초 전체 입욕 단계, 최대 10초 탐색 구간, knockdown pause와 만족도 계약을 유지한다.
- 욕탕 회수는 모든 슬롯이 비어 있고 수위가 정확히 0%일 때만 가능하다.
- 컴퓨터는 world-space monitor를 사용하고 game을 pause하거나 fullscreen viewport UI를 열지 않는다.
- 컴퓨터 사용 중 world interaction과 placement/equipment LMB는 실행되지 않고 컴퓨터 pointer가 LMB를 소유한다.
- 포커스 종료와 강제 종료 뒤 view, cursor, 입력, 이동과 interaction 상태가 기존 계약대로 복구된다.
- 기존 계약과 이번 기능이 충돌하면 기능 명세 단계로 복귀하며 아키텍처가 임의로 기존 동작을 바꾸지 않는다.

## 순환기·보일러·쿨러 설비 계약

### 공통 동작

- 세 종류는 각각 별도로 배치·회수 가능한 설비다.
- placement가 성공해 월드에 정상 설치된 순간부터 자기 종류의 용량을 제공한다.
- 들고 있는 item, placement preview, 설치 실패·취소 상태와 회수 완료 전 staged 상태는 총용량에 포함되지 않는다.
- 이번 범위에서는 설치된 설비가 항상 가동 상태다.
- 연료, 전원, 수동 펌프, 고장, 개별 On/Off와 플레이어 직접 작동 상호작용은 없다.
- customer가 이용하거나 예약하는 설비가 아니다.

### 인스턴스 용량

- 각 순환기 인스턴스는 자기 순환용량, 각 보일러 인스턴스는 자기 가열용량, 각 쿨러 인스턴스는 자기 냉각용량을 가진다.
- 첫 수직 구현의 인스턴스 기본값은 세 종류 모두 `100포인트`다.
- 인스턴스마다 서로 다른 음이 아닌 용량을 authoring할 수 있어야 한다.
- 한 설비는 자기 종류가 아닌 용량을 제공하지 않는다.
- 설비별로 특정 욕탕을 배정하거나 `몇 % 사용 중`인 상태를 만들지 않는다.
- UI의 사용량은 종류별 공용 풀 전체에 대해서만 표시한다.

### 합산

```text
총 순환용량 = 정상 설치된 순환기 인스턴스 용량 합
총 가열용량 = 정상 설치된 보일러 인스턴스 용량 합
총 냉각용량 = 정상 설치된 쿨러 인스턴스 용량 합
```

- 동일 종류 설비를 추가 설치하면 총용량은 해당 인스턴스 용량만큼 즉시 증가한다.
- 성공적으로 회수되거나 월드에서 사라진 설비는 더 이상 총용량에 포함되지 않는다.
- 설비의 외형, 위치나 footprint 크기는 제공 용량을 자동 산출하지 않는다.

## 욕탕별 순환 요구량

- 순환도는 `0~100%` 범위에서 연속으로 조절한다.
- 첫 욕탕 타입의 순환도 100% 요구량은 `100포인트`다.
- 순환 요구량은 순환도에 선형 비례한다.

```text
욕탕 순환 요구량
  = 욕탕의 100% 순환 요구량 × 순환도 / 100
```

- 첫 욕탕 타입에서 순환도 60%는 60포인트, 100%는 100포인트를 요구한다.
- 설치 욕탕별 요구량 합이 현재 총 순환용량의 사용량이다.
- 물이 0%인 욕탕도 설정한 순환용량을 즉시 예약한다.
- 실제 물이 없을 때는 순환 효과가 발생하지 않지만 예약한 용량은 다른 욕탕이 사용할 수 없다.

## 목표 수온과 가열·냉각 요구량

### 공통 실온과 목표 범위

- 프로젝트 전체가 공유하는 실온 기본값은 `20°C`다.
- 실온은 Editor에서 조정할 수 있지만 플레이 중 시간·날씨에 따라 변하지 않는다.
- 목표 수온은 욕탕별 `10~50°C`, `1°C` 간격으로 설정한다.
- 새 욕탕과 재설치 욕탕의 목표 수온은 실온에서 시작한다.

### 요구량 계산

첫 욕탕 타입의 가열·냉각 계수는 각각 `5포인트/°C`다.

```text
목표 수온 > 실온:
  가열 요구량 = (목표 수온 - 실온) × 5포인트/°C
  냉각 요구량 = 0

목표 수온 < 실온:
  냉각 요구량 = (실온 - 목표 수온) × 5포인트/°C
  가열 요구량 = 0

목표 수온 = 실온:
  가열 요구량 = 0
  냉각 요구량 = 0
```

- 한 욕탕은 가열과 냉각 용량을 동시에 예약하지 않는다.
- 물이 없는 욕탕도 목표 수온 설정에 해당하는 가열 또는 냉각 용량을 즉시 예약한다.
- 실제 순환도, 현재 수온과 목표 방향 순이동 여부에 관계없이 목표 수온과 실온 차이에 해당하는 가열·냉각 요구량을 전량 예약한다.
- 임계 순환도 이하라서 실제 수온이 목표로 이동하지 못해도 예약량을 줄이거나 반환하지 않는다.
- 목표 38°C는 가열 90포인트, 목표 40°C는 가열 100포인트를 요구한다.
- 목표 10°C는 냉각 50포인트를 요구한다.
- 설치 욕탕별 가열·냉각 요구량 합이 각각 현재 종류별 사용량이다.

## 정상 용량 제한과 슬라이더 입력

- 정상 플레이에서는 종류별 전체 요구량이 해당 총용량을 넘는 새 설정을 승인하지 않는다.
- 플레이어가 슬라이더를 움직이면 현재 조절 중인 욕탕의 제안값만 검사한다.
- 다른 욕탕의 기존 설정, 목표 수온과 순환도를 자동으로 변경하지 않는다.
- 허용 범위를 넘으려 하면 slider handle은 현재 남은 용량으로 가능한 최대값에서 멈춘다.
- 제한된 종류, 현재 사용량, 총용량과 추가로 필요한 포인트를 즉시 표시한다.
- 값을 낮춰 용량을 해제하는 방향은 항상 허용한다.
- 목표 수온을 실온 쪽으로 이동하면 기존 가열·냉각 요구량을 즉시 반환한다.
- 목표 수온이 실온을 지나면 기존 종류 요구량을 먼저 0으로 만들고 반대 종류의 남은 용량 범위 안에서 계속 이동한다.
- 총용량이 0이면 순환도는 0%를 넘길 수 없고, 목표 수온은 용량이 없는 방향으로 실온을 벗어날 수 없다.
- 드래그 중 승인된 값은 즉시 욕탕 설정과 UI에 반영된다. 별도 적용 버튼은 없다.

## 설비 회수와 총용량 감소

### 정상 회수 판정

설비 회수는 같은 종류에 대해 다음 조건을 만족할 때만 허용한다.

```text
회수 후 총용량
  = 현재 총용량 - 회수 대상 설비 용량

회수 허용
  = 회수 후 총용량 >= 현재 전체 요구량
```

- 조건을 만족하면 기존 placement 회수 흐름을 계속할 수 있다.
- 조건을 만족하지 않으면 회수를 시작하거나 완료하지 않고 부족한 포인트와 실패 이유를 표시한다.
- 회수 실패·홀드 중단·transaction 실패 뒤 총용량, 욕탕 설정과 진행 중 효과는 이전과 같아야 한다.
- 정상 회수 성공 시에만 해당 인스턴스 용량을 총용량에서 제거한다.

### 예기치 않은 설비 소실

- 파괴·비정상 제거 등으로 총용량이 현재 요구량보다 낮아져도 욕탕 설정값은 바꾸지 않는다.
- UI는 `사용량 > 총용량`을 숨기지 않고 용량 부족 상태로 표시한다.
- 부족해진 종류를 요구하는 모든 욕탕에서 해당 종류의 능동 효과를 일시 정지한다.
- 가열 부족은 가열을 요구하는 모든 욕탕의 능동 가열만 정지한다.
- 냉각 부족은 냉각을 요구하는 모든 욕탕의 능동 냉각만 정지한다.
- 순환 부족은 순환을 요구하는 모든 욕탕의 순환을 정지하고, 그에 따라 오염 감소와 능동 가열·냉각도 함께 정지한다.
- 부족하지 않은 다른 종류와 해당 욕탕의 효과는 계속 동작한다.
- 총용량이 다시 전체 요구량 이상이 되면 보존된 설정으로 모든 정지 효과를 자동 재개한다.
- 정지 중 실제 수온의 자연 실온 복귀와 손님에 의한 오염 증가는 계속 적용된다.

## 욕탕 초기 상태와 물 없음

- 선배치 욕탕, 새로 설치한 욕탕과 회수 후 재설치한 욕탕은 이번 기능에 대해 같은 초기 상태를 사용한다.
- 순환도 `0%`, 목표 수온 `20°C`, 실제 수온 `20°C`, 오염도 `0%`로 시작한다.
- 기존 계약에 따라 새 설치와 재설치는 수위 0%, 두 물 조작부 닫힘, 물 표면·물줄기 숨김으로 시작한다.
- 물이 없으면 오염 증가, 오염 감소와 능동 수온 조절은 진행되지 않는다.
- 순환도와 목표 수온 설정은 물이 없어도 유지되고 용량을 예약한다.
- 욕탕이 완전히 0%로 배수되면 실제 수온은 실온, 오염도는 0%로 돌아간다. 순환도와 목표 수온 설정은 유지한다.

## 새 물과 혼합

- 급수되는 새 물은 실온이며 오염도 0%다.
- 빈 욕탕에 처음 물이 들어오면 실제 수온은 실온, 오염도는 0%다.
- 물이 남은 욕탕에 새 물이 들어오면 기존 물과 새 물의 양 비율로 실제 수온과 오염도를 연속 혼합한다.

```text
혼합 수온
  = (기존 물 양 × 기존 수온 + 새 물 양 × 실온)
    / (기존 물 양 + 새 물 양)

혼합 오염도
  = (기존 물 양 × 기존 오염도)
    / (기존 물 양 + 새 물 양)
```

- 배수만으로 남은 물의 실제 수온과 오염 농도는 바뀌지 않는다.
- 급수와 배수가 동시에 진행되면 들어오는 깨끗한 실온 물은 계속 혼합되고, 나가는 물은 그 순간의 혼합 상태와 같은 수온·오염도를 가진다.
- 따라서 급수와 배수의 순수위 변화가 0이어도 새 물 유입이 있으면 실제 수온과 오염도는 실온·0% 쪽으로 이동할 수 있다.
- 혼합 뒤 수위는 기존 급수·배수 계약대로 `0~100%`에서 제한된다.

## 오염도 증가와 순환 정화

### 손님 오염

- 실제 입욕 중인 손님 한 명마다 오염도가 초당 `0.1%p` 증가한다.
- 같은 욕탕에서 실제 입욕 중인 손님이 여러 명이면 인원수에 선형 비례한다.
- 예약·탐색·이동·입장·퇴장·knockdown 중인 손님은 오염도를 증가시키지 않는다.
- 실제 입욕 중인 손님이 없으면 자연 오염은 발생하지 않는다.

### 순환 정화

- 유효한 순환도 100%는 오염도를 초당 `1%p` 감소시킨다.
- 정화 속도는 순환도에 선형 비례한다.

```text
초당 오염도 변화
  = 실제 입욕 손님 수 × 0.1%p
    - 유효 순환도 / 100 × 1%p
```

- 손님 오염과 순환 정화는 동시에 적용한 순변화로 관찰된다.
- 결과는 항상 `0~100%`에 머문다.
- 오염도가 0%에 도달해도 순환 설정과 용량 예약은 유지된다.
- 오염도가 100%에 도달해도 손님 행동, 입욕 가능 여부와 만족도는 이번 기능 때문에 바뀌지 않는다.
- 물이 없거나 순환도가 0%이거나 순환용량 부족 상태면 정화 속도는 0이다.

## 실제 수온 변화

### 능동 목표 수온 조절력

- 물이 있고, 순환용량이 충분하며, 목표 설정에 필요한 가열·냉각 총용량이 충분하고, 순환도가 0%보다 클 때 목표 수온 조절력이 발생한다.
- 순환도 100%의 목표 방향 조절력은 최대 `0.5°C/s`다.
- 목표 방향 조절력은 순환도에 선형 비례한다.

```text
목표 방향 조절력
  = 0.5°C/s × 유효 순환도 / 100
```

- 목표에 도달하지 않은 동안 조절력은 현재 수온에서 목표 수온으로 향한다.
- 목표에 도달한 뒤에는 같은 최대 조절력 범위 안에서 자연 실온 복귀를 상쇄해 목표를 유지할 수 있다.
- 능동 조절력 자체가 실제 수온을 목표 너머로 밀어내지는 않는다.
- 새 물 혼합으로 실제 수온이 목표에서 멀어지면 현재 설정으로 다시 목표 방향 조절력을 적용한다.

### 자연 실온 복귀와 조절력 합산

- 물이 있으면 능동 목표 수온 조절의 유무와 관계없이 자연 실온 복귀가 항상 함께 계산된다.
- 자연 복귀력의 기본값은 `0.05°C/s`이며 실제 수온에서 실온을 향해 작용한다. 실제 수온이 실온과 정확히 같으면 자연 복귀력 단독으로 수온을 움직이지 않지만, 실온 바깥의 목표를 향해 출발하려는 능동 조절력에는 현재 authoring된 자연 복귀력을 반대 방향 저항력으로 적용한다.
- 목표 방향 조절력과 자연 복귀력의 방향이 같으면 두 속도를 더하고, 반대면 작은 속도를 큰 속도에서 뺀 순속도로 이동한다.
- 자연 복귀만으로 실제 수온이 실온을 넘어가지는 않는다.
- 능동 조절을 사용할 수 없으면 자연 복귀력만 적용한다.
- 실제 수온이 실온과 목표 수온 사이에 있을 때 기본값의 실온 반대 방향 순속도는 다음과 같다.

```text
실온 반대 방향 순속도
  = 0.5°C/s × 유효 순환도 / 100 - 0.05°C/s

목표 이동·유지 임계 순환도
  = 현재 자연 복귀력 / 현재 최대 목표 조절력 × 100

기본 목표 이동·유지 임계 순환도
  = 0.05°C/s / 0.5°C/s × 100
  = 10%
```

- 실제 수온이 실온과 목표 사이에 있으면 순환도 10% 미만에서는 실온 쪽으로 이동하고, 정확히 10%에서는 현재 수온에 정체하며, 10% 초과부터 목표 쪽으로 이동한다.
- 실제 수온이 실온에 있으면 목표 조절력이 현재 자연 복귀력 이하일 때 실온에 머물고, 자연 복귀력보다 클 때만 두 힘의 차이만큼 실온 반대편의 목표를 향해 출발한다. 기본값의 경계는 순환도 10%이며 authoring 값이 바뀌면 임계 순환도도 파생 계산으로 함께 바뀐다.
- 실온과 목표 수온의 exact 경계에는 numeric epsilon을 적용하고, 경계에서 남은 힘이 이동 방향을 만들지 못하면 해당 경계에 고정해 frame 단위 왕복이나 미세 진동을 만들지 않는다.
- 실제 수온이 목표에 도달한 상태에서는 순환도 10% 이상이면 자연 복귀를 상쇄해 목표를 유지하고, 10% 미만이면 목표를 벗어나 실온 쪽으로 이동한다.
- 실제 수온 기준으로 목표 방향과 실온 방향이 같으면 임계점과 관계없이 두 효과가 합산된다. 예를 들어 실온 20°C, 실제 30°C, 목표 15°C이면 30°C에서 20°C까지 두 효과가 모두 하강 방향으로 작용한다.
- 위 예에서 실제 수온이 20°C 아래로 내려가면 자연 복귀는 상승 방향으로 바뀌어 목표 방향 조절력에서 차감된다.
- 목표 방향 조절력이 자연 복귀를 이기지 못하면 실제 수온이 목표를 통과해 실온으로 돌아갈 수 있다.

## 수온·오염도와 손님 행동의 경계

- 이번 단계에서 실제 수온, 목표 수온과 오염도는 손님의 욕탕 선택, 예약, 입장, 퇴장과 만족도를 바꾸지 않는다.
- 기존 수위 80% 조건과 슬롯 가용성만 욕탕 이용 가능성에 계속 영향을 준다.
- 수온이 매우 높거나 낮아도 이번 기능만으로 손님이 나오거나 만족도가 변하지 않는다.
- 오염도가 100%여도 이번 기능만으로 손님이 나오거나 만족도가 변하지 않는다.
- 실제 입욕 중인 손님 수는 오염도 증가에만 사용하며 customer routine의 진행을 바꾸지 않는다.
- 향후 수온·오염도에 따른 만족도와 이용 제한은 별도 기능 명세 대상이다.

## 컴퓨터 진입과 조작

- 플레이어는 기존 컴퓨터 사용 조건을 만족해 world computer에 진입한다.
- 컴퓨터 화면은 기존 world-space monitor에 표시되고 주변 world simulation은 계속 진행된다.
- 플레이어는 LMB pointer로 욕탕 footprint와 두 slider를 클릭·드래그한다.
- 컴퓨터가 LMB를 소유하는 동안 placement confirm과 equipment use는 실행되지 않는다.
- focus-in이 완료되기 전과 focus-out이 시작된 뒤에는 slider와 욕탕 선택 입력을 받지 않는다.
- focus-out 중 pointer press가 남아 있으면 입력이 안전하게 끝나며 slider가 계속 움직이거나 world LMB로 이어지지 않는다.
- 컴퓨터 또는 player가 사라지는 강제 종료에서도 마지막으로 승인된 욕탕 설정은 유지되고 플레이어 입력은 기존 계약대로 복구된다.

## 컴퓨터 UI 레이아웃

현재 `1024×576` 16:9 world screen을 기준으로 기본 Unreal UMG 디자인 요소만 사용한다.

```text
┌ 목욕탕 물 관리 ─────────────────────────────────────────────────────┐
│ 순환  [██████░░] 60 / 100   가열 [████████] 100 / 100   냉각 [░] 0 / 100 │
├ 배치영역 / 욕탕 선택 ───────────────────────┬ 선택 욕탕: 욕탕 01 ─────┤
│ +X ↑                                        │ 수위       100%          │
│ ┌─────────────────────────────────────────┐ │ 실제 수온   38.0°C       │
│ │       ┌────── 욕탕 01 ──────┐           │ │ 오염도      12%           │
│ │       │ 38.0°C / 오염 12%   │           │ ├──────────────────────────┤
│ │       └──────────────────────┘           │ │ 순환도  60% [────●────]   │
│ │                         ┌─ 욕탕 02 ─┐    │ │ 사용량  60 / 100          │
│ │                         │ 20.0°C/0% │    │ │ 목표수온 38°C [───●────]  │
│ │                         └────────────┘    │ │ 가열요구 90 / 냉각요구 0  │

└─────────────────────────────────────────────┴──────────────────────────┘
```

### 상단 총용량 영역

- 순환·가열·냉각을 각각 `현재 사용량 / 현재 총용량`과 진행 막대로 표시한다.
- 정상 범위, 가득 참과 용량 부족을 색과 text로 구분한다.
- 예기치 않은 소실로 사용량이 총용량보다 크면 진행 막대를 정상처럼 잘라 숨기지 않고 부족 상태를 명시한다.
- 개별 설비 수, 위치, 이름과 설비별 사용률은 이 영역에 표시하지 않는다.

### 욕탕 배치영역

- 현재 욕탕을 설치할 수 있는 PlacementZone 하나의 경계만 표시한다.
- 영역 안에 정상 설치된 욕탕의 실제 world X/Y 위치, Yaw와 footprint 비율을 반영한다.
- `+X`는 화면 위쪽, `+Y`는 화면 오른쪽이다.
- 실제 20cm minor grid 전체는 생략하고 위치 판독을 돕는 큰 간격 선만 표시한다.
- 순환기·보일러·쿨러와 기타 설비는 이 지도에 표시하지 않는다.
- 욕탕 footprint 전체가 하나의 선택 대상이다.
- 선택된 욕탕은 명확한 외곽선 또는 상태색으로 구분한다.
- 욕탕 타일에는 식별 이름, 실제 수온, 오염도와 정상·용량 제한 상태를 표시한다.
- 설치된 욕탕이 없으면 빈 배치영역과 `설치된 욕탕이 없습니다` 상태를 표시한다.

### 선택 욕탕 상세 영역

- 욕탕을 선택하기 전에는 선택 안내를 표시하고 slider를 비활성화한다.
- 선택 뒤 다음 항목을 표시한다.
  - 욕탕 식별 이름
  - 현재 수위 퍼센트
  - 실제 수온은 소수점 한 자리와 `°C`
  - 오염도 퍼센트
  - 순환도와 순환 요구량
  - 목표 수온과 가열·냉각 요구량
  - 기본 목표 이동·유지 임계 순환도 `10%`
  - 현재 상태와 용량 부족 이유
- 순환 slider는 `0~100%`, 목표 수온 slider는 `10~50°C`다.
- 유효 순환도가 0%보다 크면 임계 순환도 이하에서도 오염도 감소는 계속 적용한다.
- 수온의 관찰 상태는 조건에 따라 `실온 복귀 중`, `수온 정체`, `목표 수온 이동 중`, `목표 수온 유지 중`으로 구분한다.
- 용량 부족이나 물 없음 등 더 직접적인 정지 이유가 있으면 해당 이유를 위 수온 상태와 함께 또는 우선 표시한다.
- slider drag 중 승인 값과 모든 관련 숫자를 같은 화면 갱신에서 즉시 반영한다.
- UI가 실제 용량 판정을 별도로 재구현해 domain 결과와 다른 값을 표시하지 않는다.

### 기본 표현 요소

- `Border`, `TextBlock`, `Button`, `Slider`, `ProgressBar`, `Image`, `HorizontalBox`, `VerticalBox`, `Overlay`, `GridPanel` 계열과 필요한 `ScaleBox`/`ScrollBox` 수준의 Unreal 기본 요소로 구성한다.
- 순환은 초록, 가열은 주황, 냉각은 청록·파랑 계열로 구분한다.
- final custom icon, texture, font와 animation 제작은 이번 수직 구현의 필수 조건이 아니다.
- 초기 텍스트 와이어프레임과 생성된 샘플 이미지에 있던 용량 설비·기타 설비 지도 아이콘은 Q21 답변에 따라 최종 레이아웃에서 제거한다.

## UI와 월드 상태 동기화

- 설치 욕탕이 추가되면 현재 욕탕용 배치영역의 정확한 위치와 footprint로 지도에 나타난다.
- 욕탕 회수가 성공하면 지도에서 사라지고 해당 요구량이 총 사용량에서 제거된다.
- 선택한 욕탕이 사라지면 선택을 해제하고 상세 영역을 안내 상태로 돌린다.
- utility 설비가 설치·회수되면 지도에는 나타나지 않지만 상단 총용량과 각 slider의 허용 범위가 즉시 갱신된다.
- 같은 욕탕의 수위·수온·오염도·순환도·목표 수온 변화는 컴퓨터를 보고 있는 동안 연속적으로 표시된다.
- 컴퓨터 focus를 나가도 욕탕 설정과 월드 상태는 유지된다.
- 같은 world의 다른 컴퓨터에서도 동일한 욕탕 설정과 실제 상태를 본다.
- Level 재시작 뒤 상태 복원과 SaveGame 영속성은 요구하지 않는다.

## 욕탕 회수와 재설치

### 회수 홀드 중

- 기존 수위 0%와 슬롯 비어 있음 조건을 만족해야 한다.
- 회수 홀드가 진행되는 동안 순환도, 목표 수온, 실제 수온, 오염도와 예약 용량은 보이는 값 그대로 유지된다.
- 기존 물·조작부 동결 계약과 함께 이번 기능의 시간 변화도 정지한다.
- input release, 시선 이탈, target 변경, suppression, 조건 변경과 transaction 실패로 회수가 중단되면 모든 값, 용량 예약과 진행 중 효과가 시작 전과 같은 상태로 복원·재개된다.

### 회수 성공

- 욕탕이 월드에서 제거된 뒤 그 욕탕의 순환·가열·냉각 요구량은 총 사용량에서 빠진다.
- 회수 item에는 순환도, 목표 수온, 실제 수온과 오염도를 보존하지 않는다.

### 재설치

- 수위 0%, 순환도 0%, 목표·실제 수온 20°C, 오염도 0%로 시작한다.
- 두 물 조작부는 닫히고 물 표면과 물줄기는 숨겨진 기존 초기 상태를 유지한다.
- 이전 설치의 설정, 수온, 오염도와 용량 예약을 복원하지 않는다.

## 실패·취소·복구 계약

- utility placement preview 취소·설치 실패는 총용량을 바꾸지 않는다.
- utility 설치 transaction이 완료되기 전에 총용량 bar나 slider 허용 범위를 미리 늘리지 않는다.
- utility recovery hold 취소·실패는 총용량과 모든 욕탕 설정·효과를 바꾸지 않는다.
- 용량 부족으로 utility 회수를 거부해도 대상 설비는 월드에서 정상 동작하고 기존 총용량을 계속 제공한다.
- slider 입력이 제한돼도 다른 욕탕 값과 선택한 욕탕의 마지막 승인 값은 유지된다.
- 컴퓨터 pointer가 target을 잃거나 focus-out 되면 마지막 승인 값에서 drag를 끝내고 임의의 추가 변화를 만들지 않는다.
- invalid·누락된 Editor authoring은 가짜 용량이나 잘못된 화면 수치를 만들지 않고 명시적인 준비 실패로 드러나야 한다.
- 예기치 않은 설비 소실은 욕탕 설정을 자동 변경하지 않고 이 문서의 전체 정지·자동 재개 계약을 적용한다.
- 욕탕이나 computer EndPlay가 발생해도 다른 욕탕의 설정과 정상 설비 총용량을 변경하지 않는다.

## Editor authoring 기대

### 프로젝트 공통값

- 실온 기본 `20°C`
- 목표 수온 최소 `10°C`, 최대 `50°C`, 간격 `1°C`
- 값의 단위는 섭씨이며 플레이 중 동적 변경 기능은 없다.

### utility 설비 종류와 인스턴스

- 설비 종류별 기본 용량은 100포인트다.
- Level에 놓이거나 player placement로 만들어지는 각 인스턴스는 자기 종류 용량을 가진다.
- 서로 다른 인스턴스에 서로 다른 음이 아닌 용량을 authoring할 수 있어야 한다.
- visual mesh, footprint와 placement item 표현은 기능 용량과 별도로 조정할 수 있어야 한다.
- 외형 크기와 용량 사이의 자동 계산 관계를 요구하지 않는다.

### 욕탕 종류와 인스턴스

- 첫 욕탕 타입의 100% 순환 요구량 기본값 `100포인트`
- 가열 요구 계수 `5포인트/°C`
- 냉각 요구 계수 `5포인트/°C`
- 순환 100% 오염 감소 `1%p/s`
- 실제 입욕 손님 한 명의 오염 증가 `0.1%p/s`
- 순환 100% 목표 수온 변화 `0.5°C/s`
- 자연 실온 복귀 `0.05°C/s`
- 기본 목표 이동·유지 임계 순환도 `10%`
- 위 값은 욕탕 종류 기본값과 필요한 Level 개별 욕탕 차이를 authoring할 수 있어야 한다.
- property type, 저장 위치와 소유 클래스는 이 계약이 정하지 않는다.

### 컴퓨터 화면

- 현재 world screen `1024×576` 안에서 text, grid, slider와 상태가 잘리지 않고 읽혀야 한다.
- UI 지도는 DefaultMap의 단일 욕탕용 PlacementZone world X/Y와 실제 욕탕 footprint를 기준으로 한다.
- 현재 sample Widget을 교체·확장하는 asset 구조와 native binding은 설계 단계에서 정한다.
- StateTree 내부와 WidgetTree는 사전 조사 도구로 완전 확인되지 않았으므로 Editor 단계에서 실제 asset을 열어 연결을 검증해야 한다.

## 관찰 가능한 수용 시나리오

### BH-WATER-OPS-001 — 신규 상태 초기화

**Given** 선배치 욕탕 또는 새로 설치한 욕탕이 있다.
**When** 컴퓨터에서 해당 욕탕을 처음 확인한다.
**Then** 순환도 0%, 목표·실제 수온 20°C, 오염도 0%이며 이번 기능의 용량 요구량은 모두 0이다.

### BH-WATER-OPS-002 — 순환기 설치와 총용량

**Given** 총 순환용량이 0이고 기본 용량 100인 순환기 item을 배치 중이다.
**When** placement가 성공한다.
**Then** 총 순환용량이 100으로 증가하고 컴퓨터 상단에 `0 / 100`이 표시된다.

### BH-WATER-OPS-003 — 보일러·쿨러 설치와 총용량

**Given** 총 가열·냉각 용량이 각각 0이다.
**When** 기본 보일러와 쿨러를 하나씩 성공적으로 설치한다.
**Then** 가열과 냉각 총용량이 각각 100이 되고 지도에는 두 설비가 나타나지 않는다.

### BH-WATER-OPS-004 — 같은 종류 용량 합산

**Given** 용량 100 순환기 하나가 설치돼 있다.
**When** 용량 150인 다른 순환기를 설치한다.
**Then** 총 순환용량은 250이며 설비별 사용률 없이 하나의 공용 용량으로 표시된다.

### BH-WATER-OPS-005 — 배치 취소와 설치 실패

**Given** utility 설비 item을 들고 preview 중이다.
**When** 배치를 취소하거나 placement가 실패한다.
**Then** 해당 종류 총용량, 모든 욕탕 설정과 동작은 바뀌지 않는다.

### BH-WATER-OPS-006 — 컴퓨터 화면 진입

**Given** 플레이어가 기존 컴퓨터 사용 조건을 만족한다.
**When** 컴퓨터에 진입하고 focus-in이 끝난다.
**Then** 1024×576 world screen에 종류별 용량, 욕탕용 배치영역, 욕탕 타일과 상세 패널이 보이며 world simulation은 계속된다.

### BH-WATER-OPS-007 — 욕탕 지도 위치

**Given** DefaultMap 욕탕용 영역에 둘 이상의 욕탕이 서로 다른 위치와 Yaw로 설치돼 있다.
**When** 컴퓨터 지도를 본다.
**Then** +X가 위, +Y가 오른쪽인 고정 지도에 각 욕탕의 실제 위치·Yaw·footprint 비율이 반영되고 다른 설비는 보이지 않는다.

### BH-WATER-OPS-008 — 욕탕 선택

**Given** 지도에 욕탕 2개가 보이고 아직 선택한 욕탕이 없다.
**When** 플레이어가 한 욕탕 footprint를 LMB로 클릭한다.
**Then** 해당 욕탕이 선택 표시되고 상세 패널에 그 욕탕의 현재 수위·수온·오염도·순환도·목표 수온·요구량이 나타난다.

### BH-WATER-OPS-009 — 순환도와 요구량

**Given** 총 순환용량 100이고 다른 욕탕의 순환 요구량이 0이다.
**When** 선택 욕탕의 순환도를 60%로 드래그한다.
**Then** 값이 즉시 60%가 되고 순환 사용량은 60포인트, 상단 표시는 `60 / 100`이 된다.

### BH-WATER-OPS-010 — 순환용량 한계

**Given** 총 순환용량 100 중 다른 욕탕이 60포인트를 예약했다.
**When** 선택 욕탕의 순환도를 50%까지 올리려 한다.
**Then** slider는 40%에서 멈추고 전체 사용량은 100을 넘지 않으며 순환용량 제한 이유가 표시된다.

### BH-WATER-OPS-011 — 순환용량 해제

**Given** 두 욕탕이 총 순환용량 100을 모두 사용한다.
**When** 첫 욕탕의 순환도를 30% 낮춘다.
**Then** 30포인트가 즉시 해제되고 다른 욕탕 slider의 허용 범위가 그만큼 증가한다.

### BH-WATER-OPS-012 — 가열 목표와 요구량

**Given** 실온 20°C, 총 가열용량 100이며 다른 가열 요구량이 없다.
**When** 목표 수온을 38°C로 설정한다.
**Then** 목표는 즉시 38°C, 가열 요구량은 90포인트가 되고 냉각 요구량은 0이다.

### BH-WATER-OPS-013 — 냉각 목표와 요구량

**Given** 실온 20°C, 총 냉각용량 100이며 다른 냉각 요구량이 없다.
**When** 목표 수온을 10°C로 설정한다.
**Then** 냉각 요구량은 50포인트가 되고 가열 요구량은 0이다.

### BH-WATER-OPS-014 — 실온 횡단

**Given** 욕탕이 35°C 목표로 가열용량을 예약하고 있다.
**When** 목표 slider를 20°C를 지나 15°C까지 낮춘다.
**Then** 20°C에서 가열 요구량이 0이 되고, 그 아래에서는 가열 없이 냉각용량만 현재 허용 범위까지 예약한다.

### BH-WATER-OPS-015 — 목표 수온 용량 제한

**Given** 실온 20°C, 총 가열용량 100이고 다른 가열 요구량이 없다.
**When** 목표 수온을 50°C까지 올리려 한다.
**Then** slider는 가열 100포인트에 해당하는 40°C에서 멈추고 추가 50포인트가 부족하다는 결과를 표시한다.

### BH-WATER-OPS-016 — 빈 욕탕의 용량 예약

**Given** 선택 욕탕의 수위가 0%다.
**When** 순환도 100%, 목표 수온 40°C를 설정한다.
**Then** 순환·가열 사용량은 각각 100포인트로 예약되지만 오염도와 실제 수온은 물이 생길 때까지 변하지 않는다.

### BH-WATER-OPS-017 — 빈 욕탕 첫 급수

**Given** 실제 수온 20°C, 오염도 0%인 빈 욕탕에 설정이 존재한다.
**When** 급수로 처음 물이 들어온다.
**Then** 새 물은 20°C·오염도 0%이며 물이 생긴 뒤 유효한 순환·온도 조절이 시작된다.

### BH-WATER-OPS-018 — 부분 급수 혼합

**Given** 같은 양의 40°C·오염도 50% 물과 새 20°C·오염도 0% 물이 섞인다.
**When** 혼합 직후를 확인한다.
**Then** 실제 수온은 30°C, 오염도는 25%가 되고 이후 현재 순환·목표 설정에 따라 계속 변한다.

### BH-WATER-OPS-019 — 동시 급수·배수의 교환

**Given** 욕탕의 순수위 변화가 0이 되도록 급수와 배수가 동시에 진행된다.
**When** 깨끗한 실온 물이 계속 들어오고 같은 양이 나간다.
**Then** 수위는 유지될 수 있지만 실제 수온과 오염도는 실온·0% 쪽으로 연속 이동한다.

## 수직 구현 요구

이 기능은 placement, Actor lifecycle, 연속 수온·오염도, 기존 급수·배수, customer 실제 입욕 구간, world-space computer input, 동적 UI와 여러 Editor asset이 함께 바뀌므로 첫 욕탕 타입 하나의 수직 구현이 필수다.

대표 수직 흐름:

1. 첫 욕탕 타입, 순환기 하나, 보일러 하나, 쿨러 하나와 컴퓨터 하나를 준비한다.
2. utility 설비를 하나씩 배치해 세 총용량이 각각 100이 되는 것을 확인한다.
3. 컴퓨터에 진입해 욕탕용 배치영역에서 대표 욕탕을 선택한다.
4. 빈 욕탕의 순환도 100%, 목표 수온 40°C를 미리 설정해 두 용량이 각각 100 예약되는지 확인한다.
5. 욕탕을 급수해 실제 수온이 20°C에서 시작하고 순환 100%에서 목표 40°C에 약 44.5초에 도달하는지 확인한다.
6. 순환을 낮추거나 멈추고 실제 입욕 손님으로 오염도를 증가시킨 뒤, 순환을 높여 승인된 속도로 감소시키는지 확인한다.
7. 목표 50°C 시도가 보일러 하나의 용량 한계 때문에 40°C에서 제한되는지 확인한다.
8. 사용 중인 보일러 회수가 거부되고, 목표를 20°C로 돌려 가열 요구량을 해제하면 회수되는지 확인한다.
9. 컴퓨터 focus-out·재진입 뒤 상태가 유지되는지 확인한다.
10. 욕탕을 빈 상태로 회수·재설치해 모든 신규 상태가 초기화되는지 확인한다.

- 첫 욕탕 타입의 전체 흐름을 코드 리뷰, Unreal Editor 통합과 최종 통합 리뷰까지 완료한다.
- 사용자 수직 구현 승인 전에는 다른 욕탕 타입, 다중 PlacementZone UI, 연료·가동 행동과 손님 만족도 기능으로 확장하지 않는다.
- 같은 `BP_Bath`의 여러 설치 인스턴스가 공용 용량을 공유하고 지도에 나타나는 기본 다중 인스턴스 동작은 이번 계약에 포함한다.

## 아키텍처 단계의 독점 설계 영역

아키텍처 에이전트는 위 기능 결과를 바꾸지 않는 범위에서 다음을 독점해서 결정한다.

- 종류별 총용량과 욕탕 설정·실제 상태의 owner
- utility 설비와 욕탕의 클래스·Component·Subsystem·Interface 구성
- 등록·해제, 합산, 예약과 예상 밖 소실을 처리하는 내부 방식
- 수온·오염도·혼합을 갱신하는 Tick, timer, fixed step 또는 event 방식
- float 정밀도, endpoint epsilon과 화면 반올림 방식
- 실제 입욕 중 손님 수를 얻는 API와 customer session 연계
- 기존 Bath Water·Facility·Placement·Computer·UI 시스템의 의존 방향
- UI presentation data, row/tile/widget hierarchy와 native/Blueprint 책임 분리
- 기존 LMB 입력을 컴퓨터 pointer와 연결하는 방식
- placement Definition, Blueprint와 asset 생성·migration 구조
- 정상 회수 판정과 취소·rollback을 보장하는 transaction 방식
- Editor validation, logging, automation test와 runtime 진단 구조
- 현재 문서·asset 불일치의 작업 범위 포함 여부와 migration 순서
- 실제 수정·추가할 Source, Config, Content와 문서 파일 목록

아키텍처는 이 문서의 관찰 가능한 결과를 바꾸는 기술적 편의를 선택하지 않는다. 새로운 사용자 동작 선택이 필요하면 기능 명세 단계로 되돌린다.
