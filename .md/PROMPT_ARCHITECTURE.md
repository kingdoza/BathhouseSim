# 설계 입력 — 컴퓨터 포커스 진입·이탈 수정

## 목적과 상태

이미 구현된 인게임 컴퓨터의 포커스인·포커스아웃 조작을 다음처럼 고친다.

- 포커스인 직후 화면을 클릭하지 않아도 E로 바로 나갈 수 있다.
- ESC도 포커스아웃 키로 쓴다.
- 포커스인할 때마다 마우스 커서가 게임 화면 중앙에 나타난다.
- 포커스아웃하면 포커스인 직전 자리가 아니라 컴퓨터마다 정한 고정 위치·방향으로 나온다.

상태와 근거:

- 2026-09-26 사용자 요청. 사용자 선택 정본은 [QNA_FEATURE_SPEC.md](QNA_FEATURE_SPEC.md)의 `컴퓨터 포커스 진입·이탈 수정` 절 사용자 지정 사항과 Q62~Q68이다. 전체 답변 완료, 미확정 사용자 선택 없음.
- 이 기능 계약은 사용자 승인 대기 상태다. 승인 전에는 아키텍처·구현 단계로 넘기지 않는다.
- 사용자 요청에 따라 이 파일의 이전 내용(설비 노동 가동 확장 기능 계약, 사용자 승인·구현 완료)을 이 작업의 설계 입력으로 전면 교체했다.

이 문서는 플레이어 입력, 화면·월드 결과, 실패 경로, Editor 조정값과 수용 기준을 정한다. 클래스, 상태 소유자, 입력 초점 처리 방식, 입력 매핑 구성, 위치 탐색 방법, 카메라 전환 구현과 파일 구성은 설계 단계가 결정한다.

## 현재 동작과 목표 동작

근거는 현재 Source와 [Architecture/ComputerSystem.md](Architecture/ComputerSystem.md)다. 이번 명세를 위해 Editor·PIE를 새로 조사하지 않았다.

| 항목 | 현재 동작 | 목표 동작 |
|---|---|---|
| E 포커스아웃 | 포커스인 완료 뒤 화면을 한 번 클릭해야 E로 나갈 수 있음(사용자 관찰). 완료 시 키보드 입력 초점이 월드 화면 쪽으로 넘어가는 것과 관련된 것으로 보이나 원인은 확정하지 않음 | 클릭 여부와 무관하게 E 한 번으로 나감 |
| ESC | 컴퓨터 조작에 쓰이지 않음 | E 포커스아웃과 같은 결과 |
| 커서 위치 | 나타나는 위치를 중앙으로 정하지 않음 | 나타날 때마다 게임 화면 중앙 |
| 포커스아웃 위치 | 컴퓨터를 쓰는 동안 캐릭터가 진입 직전 자리에 멈춰 있고, 그 자리의 1인칭 시점으로 돌아옴 | 컴퓨터별 고정 위치·방향으로 나옴 |

사전조사 생략 근거: 고정 위치·방향과 탐색 거리는 이번에 새로 만드는 Editor 조정값이다. 기존 asset 값이 기능 결과를 정하지 않는다. 컴퓨터 Blueprint와 DefaultMap instance의 현재 연결은 [Unreal/InteractionUISystem.md](Unreal/InteractionUISystem.md)에 기록돼 있다. 실제 고정 위치 값과 주변 공간은 Editor 단계에서 정하고 확인한다.

## 포커스아웃 입력

- E와 ESC 모두 한 번 누르면 포커스아웃을 시작한다. 두 키의 결과는 같다.
- 다음 상태에서 모두 동작한다.
  - 포커스인 전환 중
  - 포커스인 완료 직후, 화면을 한 번도 클릭하지 않은 상태
  - 화면 버튼 클릭이나 슬라이더 조작을 마친 뒤
  - 슬라이더를 끌고 있는 도중
- 슬라이더를 끄는 도중 나가면 그 조작은 끝난다. 나간 뒤에 슬라이더 값이나 욕탕 설정이 더 바뀌지 않는다.
- 진입에 쓴 E를 떼거나 계속 누르고 있는 것만으로는 나가지 않는다. 한 번 누름은 한 번의 전환만 일으킨다.
- 포커스아웃 전환 중 추가 E·ESC는 무시한다. 전환이 끝난 뒤 컴퓨터를 조준하고 E를 누르면 다시 들어갈 수 있다.
- 컴퓨터를 쓰지 않을 때 ESC는 아무 동작도 하지 않는다. 배치 모드, 순환기 왕복, 회수 Hold 같은 다른 동작을 취소하지 않는다.
- ESC는 이후 범용 포커스아웃과 게임 메뉴 팝업에 재사용할 입력이다. 이번 범위에서 게임 메뉴는 만들지 않는다.

## 마우스 커서

- 커서는 기존처럼 포커스인 전환이 끝나 화면을 조작할 수 있게 되는 순간 나타난다. 전환 중과 포커스아웃 뒤에는 숨긴다.
- 나타나는 순간 커서는 게임 화면(뷰포트) 중앙에 있다.
- 매 진입마다 중앙에서 시작한다. 이전 진입에서 커서를 옮긴 위치를 기억하지 않는다.
- 커서를 중앙에 놓는 것만으로 화면 버튼 클릭이나 슬라이더 변경이 일어나지 않는다.

## 포커스아웃 위치

### 고정 위치와 방향

- 컴퓨터마다 나갈 고정 위치와 바라볼 방향(좌우·상하)을 정한다. 좌우 기울기는 없다.
- 고정 위치는 캐릭터 발바닥 위치 기준이며 컴퓨터 기준 local 좌표다. 컴퓨터를 옮기면 함께 따라간다. 발바닥 기준은 욕탕 접근·행동 지점 authoring과 같은 프로젝트 기준이다.
- 발바닥 기준이므로 바닥 높이에 둔 고정 위치로 나오면 캐릭터가 바닥에 서고 시점은 평소 눈높이가 된다.
- 바닥 높이를 찾아 맞추지 않고 authoring 값 그대로 캐릭터를 놓는다(Q68 B). 값이 바닥보다 위면 나온 뒤 일반 낙하로 아래 바닥에 선다. 떨어지는 것 외의 별도 처리는 없다.
- 고정 위치를 바닥 높이에 맞추는 것은 Editor authoring 책임이다. 바닥보다 낮게 넣으면 바닥에 끼일 수 있으므로 넣지 않는다.
- 모든 정상 포커스아웃은 진입한 위치와 관계없이 같은 자리·같은 방향으로 나온다. 포커스인 전환 중 E·ESC로 되돌아나오는 경우도 같다.

### 전환 모습

- 포커스아웃을 시작하는 순간 캐릭터를 나갈 자리로 옮긴다.
- 화면은 모니터 시점에서 나갈 자리의 1인칭 시점으로 이탈 전환 시간(기본 0.25초) 동안 부드럽게 이동한다.
- 전환 도중 포커스인 직전 자리의 시점이 보이거나, 전환이 끝난 뒤 한 번 더 순간이동하지 않는다.
- 전환이 끝나면 이동·시점·월드 상호작용이 기존처럼 돌아온다.

### 막힌 경우

- 고정 위치에 캐릭터가 설 수 없으면(손님, 물건, 벽과 겹침) 고정 위치에서 최대 100cm 안의 빈자리를 찾는다.
- 빈자리는 고정 위치와 같은 높이에서 캐릭터가 손님·물건·벽과 겹치지 않는 자리이며, 고정 위치에서 벽·물건을 통과하지 않고 닿을 수 있어야 한다. 벽 너머나 다른 방은 고르지 않는다. 높이는 Q68 B에 따라 바닥에 맞추지 않는다.
- 후보 중 고정 위치에 가장 가까운 자리로 나가며, 바라보는 방향은 고정 방향 그대로다.
- 100cm 안에 빈자리가 없으면 고정 위치로 강제로 나간다.
- 어느 경우에도 겹친 손님·물건을 밀거나 옮기지 않는다. 강제로 나간 뒤 플레이어는 일반 이동으로 빠져나올 수 있어야 하며 끼어서 움직이지 못하면 안 된다.
- 포커스아웃이 막혀 컴퓨터 화면에 갇히는 경우는 없다.

### 비정상 종료

컴퓨터가 사라지거나 플레이어·컨트롤러가 유효하지 않게 되는 비정상 종료는 기존처럼 그 자리에서 즉시 복구한다. 고정 위치 이동을 적용하지 않는다.

## 기존 기능 유지 범위

- 빈손일 때만 컴퓨터를 조준하고 E로 진입하는 조건과 안내
- 진입 0.35초·이탈 0.25초 기본 전환 시간과 조정 가능성
- 컴퓨터 사용 중 이동·시점·점프·달리기·F·G·월드 상호작용 차단
- 화면 LMB 클릭·슬라이더 조작, 욕탕 관리 화면 내용과 1024×576 world screen
- 포커스아웃해도 화면 상태를 유지하고 재진입 시 그대로 보이는 동작
- 한 컴퓨터를 한 명만 사용하는 규칙, 비정상 종료 복구
- 컴퓨터 사용 중 월드 시간 진행과 설비·욕탕 시뮬레이션
- 관련 없는 기존 결함을 포괄적으로 수정하는 작업으로 확대하지 않는다.

## Editor authoring 기대

- 컴퓨터마다 나갈 고정 위치와 방향을 조정할 수 있어야 한다. 위치는 컴퓨터 기준 local cm, 캐릭터 발바닥 기준이며 방향은 좌우·상하 도 단위다.
- Editor에서 고정 위치와 방향을 눈으로 확인하며 배치할 수 있어야 한다.
- 빈자리 탐색 최대 거리를 조정할 수 있어야 한다. 기본값 100cm.
- 고정 위치 높이는 캐릭터가 설 바닥 높이에 맞춘다. 컴퓨터가 책상 위처럼 바닥과 다른 높이에 있으면 local 높이로 보정한다.
- DefaultMap의 컴퓨터는 모니터 앞 바닥에 서서 모니터를 바라보는 자리로 고정 위치를 정한다. 정확한 값은 Editor 단계에서 실제 공간을 보고 정하며 이 문서에서 고정하지 않는다.
- 새 조정값을 추가해도 기존 컴퓨터 Blueprint·DefaultMap instance의 화면 Widget, 관리 대상 Zone 연결과 전환 시간 값이 사라지지 않아야 한다.
- 검증 환경: 사용자 Editor의 PIE 종료 키가 F2이므로 ESC 포커스아웃을 PIE에서 직접 검증한다. 이 설정은 사용자 Editor 설정이며 프로젝트 파일로 바꾸지 않는다.

## 수직 구현 판단

입력·카메라·캐릭터 위치 이동이 함께 바뀌므로 수직 구현 조건에 해당한다. 대상이 DefaultMap 컴퓨터 한 대의 흐름이라 대표 시나리오가 전체 범위와 같다. 별도 확장 단계 없이 아래 시나리오 전체를 한 단계에서 완성한다.

대표 시나리오: 컴퓨터 옆 임의 위치에서 빈손으로 진입하면 커서가 화면 중앙에 나타나고, 클릭 없이 E나 ESC 한 번으로 나오면 캐릭터가 고정 위치에 서서 고정 방향을 보고 있다.

## 관찰 가능한 수용 시나리오

| ID | Given | When | Then |
|---|---|---|---|
| CMP-001 | 포커스인 완료, 화면을 한 번도 클릭하지 않음 | E 한 번 | 포커스아웃, 고정 위치·방향으로 나옴 |
| CMP-002 | CMP-001과 같음 | ESC 한 번 | CMP-001과 같은 결과 |
| CMP-003 | 포커스인 전환 중 | E 또는 ESC | 포커스아웃으로 바뀌고 고정 위치·방향으로 나옴 |
| CMP-004 | 화면 버튼 클릭 또는 슬라이더 조작을 마친 뒤 | E 또는 ESC 한 번 | 포커스아웃. 재진입 시 마지막 화면 상태 그대로 |
| CMP-005 | 슬라이더를 끄는 도중 | ESC 또는 E | 포커스아웃, 나간 뒤 슬라이더 값·욕탕 설정이 더 바뀌지 않음 |
| CMP-006 | 컴퓨터 조준, 빈손 | E를 눌러 진입하고 전환이 끝날 때까지 누르고 있다가 뗌 | 진입 유지, 떼는 것만으로 나가지 않음 |
| CMP-007 | 포커스인 | 커서가 나타나는 순간 확인 | 커서가 게임 화면 중앙, 클릭·값 변경 없음 |

## 비목표와 설계 자유 영역

이번 범위에 포함하지 않는 기능:

- 게임 메뉴·일시정지 화면, ESC의 범용 포커스아웃 적용과 다른 모드 취소
- 키 재설정 UI, 새 컴퓨터 프로그램·화면
- 커서를 뷰포트 안에 가두는 동작 변경
- 포커스인 시 캐릭터를 미리 고정 위치로 옮기는 동작
- 나갈 자리의 바닥 높이 자동 맞춤과 바닥 높이 Editor 경고
- 컴퓨터 여러 대 동시 사용, 멀티플레이, 저장

설계 단계는 기존 정본·Source를 근거로 입력 초점 처리, ESC 입력 연결, 커서 배치 시점, 나갈 자리 판정과 탐색, 캐릭터 이동과 카메라 전환의 연결, Editor 표시 방식과 검증 방법을 독립적으로 결정한다. 설계 결과는 [AGENT_ARCHITECTURE.md](AGENT_ARCHITECTURE.md)의 소유권·산출물 규칙을 따른다. 이 기능 입력 작성만으로 Source·Content 구현이나 Editor 수정을 시작하지 않는다.
